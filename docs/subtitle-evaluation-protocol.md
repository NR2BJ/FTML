# 자막 보정 평가 절차

## 목적과 판정 한계

신고된 한 장면의 변화와 여러 영상의 품질 향상을 구분한다. 새 모델이나 보정을 먼저 채택하지 않고, 같은 인식 원문에서 보정을 하나씩 제거하여 효과와 부작용을 비교한다. 운영 코드의 시각 규칙은 이 검사 도구를 추가했다는 이유로 바꾸지 않는다.

`timing_evaluation.py`는 모델 없이 실행한다. 사람이 확인한 정답이 없으면 모든 후보의 품질은 **미검증**이다. 짧은 표시·반복·겹침 개수는 청취할 위치를 찾는 지표이며 오류율이 아니다. 짧은 맞장구와 여러 화자의 겹친 말은 정상일 수 있다. 이 수치를 줄이는 방향으로 자동으로 자막을 합치거나 삭제하지 않는다.

## 평가 자료를 먼저 고정한다

- `work_id`는 작품을 식별한다. 같은 작품의 회차나 구간을 개선 자료와 독립 평가 자료로 나누지 않는다. 도구는 한 평가 묶음 안의 작품 분리 위반과 중복 ID를 거절한다. 과거에 이미 보고 조정한 작품인지까지 자동으로 판별하지 못하므로 이력도 확인해야 한다.
- `development`는 원인 분석과 수정용, `validation`은 후보 선택용, `holdout`은 선택 완료 후 독립 평가용이다. 독립 평가 결과를 보고 규칙을 조절했다면 다음 평가에서는 더 이상 미사용 자료가 아니다.
- 정상 대화의 무작위 구간과 긴 공백·노래·겹친 화자 등의 어려운 구간을 함께 고정한다. 문제가 나온 구간만 골라 구성하지 않는다. 언어·작품·인식기별 결과를 분리하고 평균 하나로 합격시키지 않는다.
- 실제 인식은 운영 입력 길이와 앞뒤 문맥을 유지한다. 짧은 구간만 다시 인식한 결과를 원래 전체 추출의 재현이라고 부르지 않는다. 초기 검사는 5분 연속 입력도 사용할 수 있으나, 전체 영상·여러 창 연결·후반부 품질 보증과 구분한다.
- 원음, 모델/코드 버전, 트랙, 입력 시작·길이, 원문 해시, 단계 기록을 비공개로 보존한다. 영상·대사·실제 파일명·호스트 주소는 공개 저장소에 넣지 않는다.

## 단계 기록에서 비교 입력 만들기

Linux 격리 컨테이너 안에서만 실행한다. 운영 추출이 끝난 상태에서 CPU2개·메모리와 스왑 합산5GiB 등의 한도를 적용하고, 원음·모델 캐시는 읽기 전용으로 연결한다. 네트워크를 차단하고 실행 시간 한도도 설정한다. Mac에는 모델을 올리지 않는다.

```sh
python3 /app/benchmark.py /probe/audio.wav \
  --model OpenVINO/whisper-large-v3-int8-ov --language ja \
  --trace --evaluation-id sample-whisper --work-id work-a --split development \
  --output /output/new-capture
```

완료 후 `evaluation-snapshot.json`에는 말소리 경계 보정 전 원문, 실제 검출 구간, 적용 설정, 최종 자막이 담긴다. 새 `timing_experiment_context` 기록이 없는 예전 파일은 필요한 관측치를 추정하지 않고 변환을 거절한다. 작업이 끝나지 않았거나 여러 작업이 섞인 기록도 거절한다. 원본 최종 결과를 가진 비교 입력은 재실행한 현재 후보가 그 결과와2ms 이내에서 같아야 한다. 다르면 설정·코드·모델 차이를 먼저 해결한다.

Qwen 인식과 공식 정렬기를 함께 실행했을 때 메모리 한도를 넘는 환경에서는 순차 분리해 수집할 수 있다. 다만 이때 원래의 예외 재인식·창 연결까지 재현했는지 명시한다. 실패 구간을 뺀 결과를 완전한 영상 결과로 평가하지 않는다.

## 보정을 하나씩 제거한다

이미 설치된 음향 모델을 지정해 오프라인으로 실행한다. 각 비교 입력은 최대15분, 한 번에 읽는 음성은 최대30초다. 결과 파일을 덮어쓰지 않는다.

```sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
python3 /app/timing_experiment.py /output/new-capture/evaluation-snapshot.json \
  --audio /probe/audio.wav --acoustic-model-path /models/설치된-음향-모델 \
  --output /output/new-comparison.json
```

후보 구성:

- `no_optional_timing`: 말소리·음향 보정 없이 고정 원문을 공통 표시 처리한다. **모델의 완전한 원시 결과가 아니다.** 원문 투영, Qwen 앞선 재정렬, 창 연결은 이미 포함돼 있다.
- `current`: 기록된 설정의 말소리·음향 보정과 공통 표시 처리를 적용한다.
- `without_acoustic`: 일본어 음향 대조만 제거한다. 다른 언어에 일본어 음향 모델을 적용하지 않는다.
- `without_speech`: Whisper 말소리 보정만 제거한다. 입력이 바뀌면 그 뒤 음향 대조도 다시 실행한다. 보정 후 음향 결과를 그대로 재사용해 제거 실험으로 위장하지 않는다.
- `without_hold`: Qwen의 짧은 표시 연장만 제거한다.

모든 후보에 같은 묶기와 완전한 디지털 무음 처리를 적용한다. 원문 해시를 원래 입력과도 비교하므로 모든 후보에서 똑같이 대사가 사라져도 감추지 않는다. 후보 간 새 경계에는 글자별 가상 시각을 만들지 않고 비교 불가로 표시한다. Qwen 재정렬·창 연결 자체의 제거 및 서로 다른 묶기 알고리즘의 비교는 별도 후속 범위다.

## 모델 없는 평가와 정답 검수

```sh
python3 whisper/timing_evaluation.py /private-results/*-comparison.json \
  --output /private-results/new-report
```

결과 폴더0700, 파일0600이며 기존 결과를 덮어쓰지 않는다. Mac의 메모리 사용을 제한하도록 한 번의 입력 파일 합계는32MiB 이하만 허용한다. `report.md`에는 원문 대사를 넣지 않는다. 상세 변화량과 제한된 검토 후보는 `report.json`에 저장한다. `review_candidates`는 후보별 시간순 목록을 번갈아 뽑으며 오류 순위가 아니다. 기본 최대60개 이후도 원본 지표에서 확인할 수 있다. 글자 대응에서는 공백을 제외하되 공백 포함 원문 보존 여부도 별도로 기록한다.

정답이 없으면 `no_reference`, 인식 문구와 정답 문구가 다르면 `reference_text_mismatch`다. 맞는 일부만 골라 채점해서 점수를 부풀리지 않는다. 현재 도구는 원문을 고정한 시각 비교용이므로 인식 오인식률이나 번역 품질은 채점하지 않는다.

실제 음성을 확인한 경우에만 실험 파일에 다음과 같은 `reference`를 붙인다. 예시는 설명용이며 실험 자료로 사용하지 않는다. 허용 범위는 평가 전에 정하고 명시한다. 모델의 두 결과가 일치하거나 기존 자막에 시각이 있다는 이유만으로 사람이 검수한 것으로 표시하지 않는다.

```json
{
  "reference": {
    "verified_by": "human",
    "annotator": "검수자 식별값",
    "cues": [
      {"text": "예시 발언", "start_ts": 1.0, "end_ts": 2.0,
       "onset_range": [0.9, 1.1], "offset_range": [1.9, 2.1]}
    ]
  }
}
```

시작·끝 오차의 중앙값/95백분위/최악값, 선행·지연 표시, 조기·늦은 소멸, 발언 내부의 표시 공백을 따로 확인한다. 마지막 지표의 공백이 모두 오류라는 뜻도 아니다. 검수된 문장 안의 실제 쉼인지 원음과 비교해야 한다. 정답 채점 수치가 생겨도 자동 합격을 내리지 않는다.

SubER처럼 원문·분할·시각을 함께 평가하는 외부 지표도 후속 보조 수단이 될 수 있지만, 현재 도구에는 설치·연동하지 않았다. [SubER 논문](https://aclanthology.org/2022.iwslt-1.1/), [공식 구현](https://github.com/apptek/SubER).

## 채택 조건

새 후보를 적용하기 전에 기존 보정 제거 결과부터 본다. 원문 누락·추가, 다른 언어 적용, 정상 반복 삭제 같은 확인 가능한 위반은 먼저 탈락시킨다. 남은 후보는 정답이 있는 개선 자료에서 손익을 측정하고 다른 작품에서 재확인한다. 평균만 좋아지고 일부 발언이 심하게 악화되면 채택하지 않는다. 메모리·처리 시간도 함께 기록한다.

정답 자료가 없는 초기 실행은 수집·비교 체계 검증과 청취 후보 선별까지만 완료로 본다. 그러한 실행 뒤에 "전체 품질 향상"을 이유로 기본 보정을 바꾸지 않는다. 사용자가 매번 영상 전체를 보며 신고하는 대신 짧고 재현 가능한 비교 묶음을 남기는 것이 이 단계의 산출물이다.
