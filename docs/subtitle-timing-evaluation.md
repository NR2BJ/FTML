# 자막 시각 검증

고정 원문에서 보정을 제거해 비교하는 절차와 정답 없는 지표의 한계는 [자막 보정 평가 절차](subtitle-evaluation-protocol.md)에 정리한다.

## 원문과 시각을 분리해서 본다

인식된 대사가 틀린 것과, 맞는 대사가 잘못된 시각에 표시되는 것은 별개다. 최종 VTT만으로 둘을 구분하지 않는다.

1. 원음은 선택한 음성 트랙을 PTS를 보존하는 16kHz 모노 WAV로 변환한다. VAD로 자르거나 잡음 제거/보컬 분리로 바꾸지 않는다.
2. 인식 원문을 고정한다. 일반적인 Qwen 재정렬과 Whisper의 말소리 경계 보정은 새 단어를 생성하지 않는다. 사용자 용어 힌트는 인식 결과에 영향을 줄 수 있다.
3. 원시 단어 시각, 시간 보완, 겹친 창 연결, 표시 묶음, 짧은 표시 연장을 각각 비교한다.
4. 예외는 Qwen 정렬 실패 구간의 분할 **재인식**이다. 이때는 ASR을 다시 실행하므로 문구가 달라질 수 있다. 겹친 창 연결 역시 서로 다른 인식 결과 중 하나를 선택한다. 원문 유지 재정렬과 구분해야 한다.

공통 단어 대응 처리에서는 길이 0인 단어도 원문상의 위치와 모델 시각을 남긴다. 이 정보를 버리고 문장 시작부터 다음 단어까지 전부 채우던 경로를 제거했다. 시각이 맞닿은 앞/뒤 조각은 원문을 보존하며 이웃 표시와 함께 처리하고, 그 묶음을 정확한 단어 시각으로 표시하지 않는다. 불일치/역전/근거 없는 원문에는 이 규칙을 적용하지 않는다. 모든 단어가 불확실한 경우에는 여전히 모델의 문장 시각이 필요하다. 양수 길이지만 잘못 배치된 시각까지 해결하지는 않는다.

## 단계별 기록

`benchmark.py --trace`는 검사 출력 폴더에 `stages.jsonl`을 만든다. 기본 실행과 HTTP 작업에서는 기록하지 않는다. 파일 권한은 0600이며 기존 기록을 덮어쓰지 않는다. 16MiB를 넘으면 검사를 중단한다. 기록에는 대사가 있으므로 공개 저장소에 올리지 않는다.

주요 단계는 `model_output`, `word_projection`, `window_stitched`, `before_speech_boundaries`, `after_speech_boundaries`, `grouped`, `display_hold`, `final`이다. Qwen에는 `qwen_recognized`, `qwen_aligned`, `qwen_sentence_refined`, `qwen_context_refined`, `qwen_normalized`가 추가된다. `recognition_retry`는 원문을 다시 인식한 예외 경로다. 시각 단위는 초이며 모델별 창 안 시각과 절대 시각을 구분하기 위해 `offset`을 함께 기록한다.

실제 모델 검사는 Linux 격리 컨테이너에서만 한다. Mac에서 `benchmark.py`나 아래 도구를 실행하면 모델을 가져오기 전에 거절한다. 모델/미디어는 읽기 전용, 출력은 별도 폴더, 네트워크는 차단하고 메모리와 스왑 합산 한도, CPU 수, 실행 시간 한도를 설정한다. 운영 추출이나 변환과 동시에 실행하지 않는다.

## 독립 비교 도구

`alignment_probe.py`는 운영 추출 경로와 분리된 검사다. `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, 기존 `--model-path`가 필수다. 새 모델을 자동으로 받지 않으며 최대 30초 입력 12개를 순서대로 처리한다. FFmpeg 재표본화 끝에 붙은 10ms 이하의 초과 샘플만 30초로 제한한다.

```sh
python3 /app/alignment_probe.py whisper-native \
  --inputs /probe/inputs.json --model-path /models/기존-모델-경로 \
  --output /output/새-검사-폴더
```

입력 JSON 예시:

```json
[{"audio":"/probe/clip.wav","language":"ja","offset":0}]
```

- `whisper-native`: 단어 시각 끔/켬의 원문·문장·단어 결과를 따로 저장한다. 외부 보정 전 결과다.
- `qwen-native`: 정렬기 없이 Qwen ASR만 실행하여 원문을 저장한다. `ja`, `ko`, `en`을 지원한다.
- `qwen-scores`: 입력에 `text`와 `language`(`Japanese`, `Korean`, `English`)를 넣는다. 공식 정렬 결과와 원시 시각 점수, 단어 순서를 지키는 최대 점수 경로 두 가지를 저장한다. 길이 0 허용과 최소 한 칸 길이를 강제한 결과를 모두 비교한다. 강제로 길이 0을 없앴다는 사실은 정확도 개선을 뜻하지 않는다.
- `ctc-ja`: 기존 별도 일본어 CTC 모델에 같은 원문을 입력한다. 입력의 `texts`는 `{"whisper":"인식 원문", "qwen":"인식 원문"}` 형태다. 글자별 음향 대응 시각과 점수를 저장한다. 어휘에 없는 글자를 삭제하거나 임의 보간하지 않고 해당 원문을 비교 불가로 기록한다. 한국어·영어 CTC는 이 도구에서 검증하지 않았다.

CTC의 글자 활성 시각은 곧바로 읽을 수 있는 자막의 시작·끝이 아니다. 음향 점수도 실제 정확도를 보장하는 확률이 아니다. 단어 분절·무음·표시 길이는 별도로 평가해야 한다. 어느 비교 도구도 운영 자막을 저장하거나 기본 정렬기를 교체하지 않는다.

## 2026-10-11 검사 범위

- Debian A380의 Whisper large-v3 INT8과 Qwen3-ASR 1.7B INT8을 순차 실행했다. 일본어 애니의 여섯 30초 구간과 별도로 지정받은 한국어 예능·영어 영화의 각 10초 구간을 사용했다. 한국어·영어는 처음에 30초로 기록했으나 재표본화 전 샘플 수를 제한한 검사 준비 오류를 발견해 실제 길이로 정정했다. 전체 영상 평가는 아니다.
- Whisper의 단어 시각 끔/켬 16회에서 각 쌍의 인식 문구가 같았다. 여덟 결과 모두 공통 처리 전후의 글자를 보존했다. 일부 오인식과 감사 환각은 인식 직후 원문에 이미 있었다. Qwen에서도 잘못된 이름 표기를 정렬 전 ASR 원문에서 확인했다.
- Qwen 공식 정렬기의 원시 점수를 여덟 구간에서 저장했다. 순서 제약만 바꾸는 후보는 길이 0을 늘리는 구간도 있었고, 최소 길이를 강제해도 잘못된 발언에 붙은 단어가 해결되는 것은 아니었다. 운영에는 적용하지 않는다.
- 일본어 CTC `jonatasgrosman/wav2vec2-large-xlsr-53-japanese`의 고정 버전 `cf031e020336460d15a417eba710bbc5bb43be9a`를 별도 검사했다. 여섯 구간의 두 원문 중 8개를 정렬했고 4개는 미지원 한자 때문에 거절했다. 일부 긴 선행 표시가 줄어드는 후보와 서로 다른 입력 창의 일관성을 확인했으나, 약한 음향 점수·미지원 글자·짧은 글자 표시 문제가 있어 기본값으로 채택하지 않았다.

정확한 발화 시각을 사람이 표시한 정답 자료와 미사용 영상 검증은 아직 없다. 따라서 지연 오차의 평균, 전체 품질 향상률, 음악/작은 목소리/겹친 화자의 개선을 주장하지 않는다. 후속 채택 조건은 원문 보존, 미지원 글자 처리, 실제 발화와의 오차 감소, 다른 영상에서의 회귀 없음, 자원 사용 한도다.

후속 구조는 **인식 원문 확정 → 원음과 원문을 대조한 별도 정렬 → 발언 경계에 따른 표시 묶음**으로 나눈다. 위 비교 모델은 기본값으로 채택하지 않았다. 다음 후속 단계에서는 어휘가 다른 일본어 음향 모델을 사용하고 미지원 단어를 원래 시각으로 보존하는 제한적 대조를 구현했다. 시각 수정을 이유로 인식 원문을 다시 생성하는 경로와는 구분한다.

최종 코드의 Whisper 30초 실제 실행에서도 여덟 단계 기록과 원문 글자 보존을 확인했다. 이 검사는 말소리 경계 보정을 끈 상태로 기록/공통 처리 경로를 검증한 것이며 기본 설정의 전체 품질 시험은 아니다. Mac에서는 모델 없이 자동 시험 132개를 실행했다. 서버에 만든 비교용 CTC 모델과 임시 컨테이너는 검사가 끝난 뒤 제거하며 운영 모델 캐시·자막·서비스는 변경하지 않는다.

## 후속 첨부본에서 확인한 미해결 증상

2026-10-11의 Qwen 자동 감지 VTT에서는 03:54.760~03:57.880 묶음 끝의 `すぐ`와 다음 `慣れますよ。`가 분리되어 있고, 뒤쪽은 04:00.120~04:00.200의 80ms로 남아 있다. 이전 공통 단어 대응 수정으로 이 문제가 해결되었다고 볼 수 없다. 03:50.680~03:53.800 묶음이 실제보다 먼저 보인다는 사용자 보고도 남아 있다. VTT에는 원시 정렬 시각과 보정 과정이 없으므로 새 결과의 정확한 발생 단계를 단정하지 않는다. 이 첨부본 확인에서는 모델을 재실행하거나 시각 보정 규칙을 추가하지 않았다. 단순 표시 연장은 바로 맞닿은 다음 발언을 침범하므로 원음 대조 없이 적용하지 않는다.

## 참고 구현

- [Qwen 공식 정렬기](https://github.com/QwenLM/Qwen3-ASR/blob/main/qwen_asr/inference/qwen3_forced_aligner.py): 개별 시각 선택과 순서 보정 구조.
- [OpenVINO Whisper 단어 시각](https://github.com/openvinotoolkit/openvino.genai/blob/master/src/cpp/src/whisper/word_level_timestamps.cpp): 단어 시각 계산과 후처리 구조. 실제 검사는 고정 배포 버전으로 수행한다.
- [WhisperX 정렬 구현](https://github.com/m-bain/whisperX/blob/main/whisperx/alignment.py): 인식 문구와 별도 CTC 정렬을 분리하는 비교 방향의 참고. WhisperX 자체를 운영에 설치하지 않았다.
- [일본어 CTC 모델 설명](https://huggingface.co/jonatasgrosman/wav2vec2-large-xlsr-53-japanese): 검사 모델의 어휘·학습 자료·제약 확인용. 해당 모델의 공개 정확도는 이 서비스의 자막 정확도가 아니다.

## 일본어 공통 음향 대조 추가

Whisper/Qwen의 일본어 결과에 `acoustic_timing.py`와 `japanese_timing.py`를 공통 적용한다. 파일명·작품명·문제 시각·특정 대사에 대한 예외는 없다. 인식이 끝나고 기존 겹침 연결·말소리 경계 처리를 마친 뒤, 인식 모델을 메모리에서 해제하고 별도 CPU 모델로 **고정된 원문과 원음의 대응**을 구한다. 새로운 문구를 생성하거나 기존 대사를 삭제하는 단계가 아니다. 한국어·영어에는 일본어 음향 모델을 적용하지 않는다.

- 모델은 [Reazon 일본어 wav2vec2](https://huggingface.co/reazon-research/japanese-wav2vec2-large-rs35kh)의 고정 버전 `2162c9edb97f362f7623d6b3a2e417458e879bca`다. 기존 Whisper/Qwen 인식 모델을 바꾸는 것이 아니다. 처음 사용할 때 약 1.3GB 가중치를 `/models`에 추가로 저장하며, 음성·대사는 외부로 전송하지 않는다.
- 최대30초씩 CPU 두 스레드로 대조한다. 가능한 기존 발언 끝에서 검사 범위를 나누며, 원문·시각을 가진 단어를 복제하지 않는다. 같은 음성을 다시 읽는 여유 구간은 있을 수 있지만 재인식·겹침 문구 선택은 하지 않는다.
- 문장부호는 음향 대응 대상에서 제외하되 출력 원문에는 그대로 보존한다. 미지원 글자·약한 음향 대응·과도한 이동·이웃 침범은 기존 단어와 시각으로 돌아간다. 미지원 단어 하나 때문에 다른 발언 전체를 포기하지 않는다.
- 강제 경로의 점수와 독립 최댓값 경로의 일치를 함께 검사한다. 이 점수는 정확도 확률이 아니다. 짧은 읽기 여유만 붙이고, 이웃과 여유만 겹치면 그 여유만 줄인다. 실제 음향 근거를 자르거나 다음 화자를 밀지 않는다. 새 경계가 기존의 짧은 불확실 조각을 고립시키면 교체를 취소한다.
- 처리 가능한 모델 준비·메모리·호환성 오류는 기존 결과로 저장하고 완료 안내에 대조 미적용을 표시한다. 컨테이너 자체가 OOM으로 강제 종료된 경우까지 복구하지는 못한다. 취소는 성공으로 바꾸지 않는다. 추출 정책 버전은 Qwen6, Whisper4다. `JAPANESE_ACOUSTIC_TIMING=false`로 이 추가 단계만 끌 수 있다.

### 후속 검증과 남은 한계

일본어 여섯30초의 저장된 실제 Whisper 원문·단어 결과와, Qwen 인식 후 정렬기를 따로 실행한30초 결과를 고정하여 대조했다. Qwen ASR과 공식 정렬기를 동시에 실행한 검사 컨테이너는5GiB 한도에서 OOM이 발생했으므로 한도를 올리지 않고 분리했다. 최종 음향 대조는4GiB 한도에서 완료했다. 운영 서비스·운영 모델 캐시는 변경하지 않았다.

별도로 이전 Qwen 원문·공식 원시 정렬 여섯30초도 고정해서 대조했다. 이 검사는 기존 재정렬 보완을 다시 실행한 전체 요청 검사가 아니라 원시 정렬 이후 공통 단계의 비교다. 모두 원문 글자 보존과 실행 완료를 확인했으며, 채택 수가 많다는 사실 자체를 정확도 향상률로 해석하지 않는다. 낮은 대응 때문에 유지된 문장 조각도 남아 있다.

Whisper는 실제 인식부터 최종 VTT까지 문제 구간, 사용하지 않았던 뒤쪽 구간, 별도 일본어 작품의 각30초에서 실행했다. 일본어 대조 채택은 각각13/5/2개 발언이며5GiB 한도 안에서 완료했다. 한국어·영어도 샘플 준비를 수정한 실제30초 입력으로 실행해 일본어 단계가 적용되지 않는 것을 확인했다. 이 두 언어의 정렬 품질이 향상됐다는 뜻은 아니다.

문제 영상의 저장된 원문 비교에서는 Whisper의 약178.38초 시작이 약180.53초로 이동했고, Qwen의 뒤쪽 발언으로 밀린 문장 끝이 약238.32~239.43초에 앞 단어와 함께 배치됐다. 이는 해당 음향 모델의 대응과 사용자 보고 방향이 맞는 사례이지, 사람이 표시한 정답과의 오차 측정은 아니다. Qwen의 일부 짧은 말·낮은 대응 구간은 여전히 기존 시각을 사용한다. 전체 영상, 노래, 겹친 화자의 회귀 없음이나 모든 타이밍 문제 해결을 주장하지 않는다. 그래서 완료 화면에도 실험 단계임을 표시한다.

`acoustic_evidence`, `acoustic_proposals`, `acoustic_review` 기록을 기존 비공개 단계 기록에 추가했다. 향후 남은 문제는 최종 VTT만으로 추정하지 않고 이 기록과 원음을 비교한다. 기존 자막을 소급 수정하지 않으므로 새 방식 비교에는 다시 추출이 필요하다.

## 후속 경계·중복 보완

Qwen7/Whisper5 정책에서는 다음 공통 경로를 보완한다. 작품명·파일명·대사·특정 재생 시각 조건은 없다.

- 겹쳐 인식한 창을 연결할 때, 시각이 조금 다른 같은 문장 끝을 누락 대사로 다시 추가하지 않는다. 서로 다른 두 추론의 연결 부근에서 연속 네 글자 이상이 대응하고, 반대쪽 선택 결과에 해당 조각 전체가 포함된 경우만 복구에서 제외한다. 같은 추론의 반복 대사·짧은 맞장구 하나만으로는 제거하지 않는다.
- 음향 대조의 앞뒤 음성 여유에는 이웃의 원문도 포함한다. 단어 시각이 없는 이웃 문장 하나까지 범위를 조금 넓힐 수 있지만 최대30초, 가까운5초 안의 이웃, 총420글자 한도를 지킨다. 이웃 문구는 문맥으로만 쓰며 소유한 자막을 중복 생성하지 않는다. 분절이 소유권 경계를 가로지르면 그쪽 문맥을 제외한다.
- 음향과 원래 시각 모두 쉼을 지지하는 쉼표 경계에서는 불확실한 감탄사와 뒤 문장을 따로 검토한다. 앞 조각 때문에 잘 대응하는 문장 전체를 포기하지 않는다. 정상적인 쉼표마다 자막을 더 잘게 나누는 규칙은 아니다.
- 긴 선행 표시의 앞 연속 두 글자 이상이 충분히 대응하면, 끝이 불확실하더라도 시작만 늦출 수 있다. 원래 끝 시각·원문을 보존하며, 이웃 침범·원래 겹침 보호는 그대로 적용한다.
- 전체 대응은 충분하지만 끝 글자가 불확실한 후보는 짧은 다른 범위로 재대조한다. 모든 분절의 글자 범위가 같고 시작·끝 차이가 각각120ms 이내일 때만 두 결과의 글자 근거를 보완한다. 양쪽 모두 근거가 없으면 채택하지 않는다. 첫 대조의 시각을 유지하며 평균 시각을 만들지 않는다. 기존 점수·이웃 검사도 통과해야 한다. 한 기본 검사 구간당 최대2회, 재검사 음성은 최대12초다. 추가 CPU 시간이 발생하지만 새로운 모델은 받지 않는다.

완료 안내의 `timing_acoustic_rechecks`는 재대조 시도, `timing_acoustic_recovered`는 이웃 보호까지 통과한 보완 수다. `acoustic_recheck`에는 비공개 검사에서만 두 범위의 시각 근거를 기록한다. 재대조는 재인식이나 문구 교정이 아니다.

단어 시각을 문장 경계 밖으로 그대로 허용하는 별도 후보도 검사했지만, 인식 원문에 이미 반복·시각 역전이 있는 경우 단어가 서로 섞일 수 있어 채택하지 않았다. 인식 단계 자체의 반복이나 오인식까지 이 변경으로 제거했다고 보지 않는다. 특히 한쪽에서만 인식된 고유명사와 약한 소리에는 기존 시각이 남을 수 있다.

### 후속 실제 검사 결과

2026-10-11 후속 검사에서는 운영과 같은 Qwen30초 창8개를 인식한 뒤 공식 정렬을 별도 실행했다. Whisper는0~300초 및295~595초의 두 창을 실제 인식해 연결했다. 이 원문들을 고정하고 기존/수정 음향 대조를 비교했다. 모든 모델 실행은 서버의 CPU2·메모리와 스왑 합계5GiB 제한 컨테이너에서 순차 진행했고 OOM 없이 끝났다. Mac에서는 모델 없는 시험만 실행했다.

- Whisper5:16의 고립된 첫 글자는 전체 문맥에서 재현됐다. 앞 문장의 같은 음절을 잘못 선택하던 것이 이웃 원문을 포함한 대조에서 사라졌고 문장 시작은317.070초로 모였다. 5:26의 다른 문장은326.040초에서327.178초로 시작만 늦췄으며 원래 끝327.920초를 보존했다.
- Qwen4:32의 짧은 이름은274.480초에서271.701초로, 별도 문장 끝은275.360초에서273.507초로 이동했다. 5:21~24의 고립된 문장 끝은 각각320.329~321.494초,321.860~322.595초의 문장 묶음으로 합쳐졌다. 이 수치는 음향 대조 결과이지 수동 정답과 비교한 정확도 점수가 아니다.
- Qwen의 겹친375/400초 창 연결에서는 원래 같은 발언의 끝을 한 번 더 복구하던 중복만 제거됐다. 그러나6:45 끝 글자의 음향 근거는 최종 조건을 충족하지 않아 여전히 기존의 짧은 시각으로 남았다. 8:38 부근의 이름 오인식과 압축된 시각도 미해결이다.
- 별도 일본어 작품의 이전 Whisper 원문과 실제30초 원음에도 새 대조를 실행해 원문 보존과 처리 완료를 확인했다. 이 검사는 새 ASR 실행이나 청취 정답 검사, 다른 영상 전체의 회귀 없음 보증은 아니다. 이번에 한국어·영어 모델을 다시 실행하지 않았으며 일본어 전용 적용 조건은 자동 시험으로 확인했다.

최종 비교에서 Qwen은11회 재대조 중1개, Whisper는22회 중7개 발언이 이웃 보호까지 통과했다. 재대조 채택률이나 짧은 자막 개수 감소만으로 품질 향상률을 주장하지 않는다. 기존 번역은 시각을 소급 갱신하지 않으므로 새 추출 뒤 다시 번역해야 한다.

## 시각 근거 보존과 표시 경계 분리

Qwen8/Whisper6 정책에서는 모델의 원문이나 발화 인식 설정을 바꾸지 않고 다음 두 정보 손실을 막는다. 파일명·작품명·특정 대사·재생 시각 조건은 없다.

- Qwen 정렬에서 길이가0인 단어를 이웃과 합치거나 임시80ms로 늘렸다면 `_timing_uncertain`을 남긴다. 원문 표기 복원·단어 투영·창 연결까지 이 표시를 보존한다. 임시 시각은 모델이 직접 반환한 유효 단어 시각처럼 창 연결의 기준이 되지 않는다. 문구와 표시용 시각을 지우거나 강제 이동하는 수정은 아니다. 한국어·영어에도 같은 규칙을 적용한다.
- 일본어 음향 분절 하나가 원래 두 발언 경계를 가로지르면, 그 안의 글자 시각을 나누어 추정하거나 두 발언을 합친 자막을 채택하지 않는다. 시작만 확신할 수 있는 경우에는 첫 발언의 시작만 늦추고, 그 발언의 끝과 뒤 발언들의 시각·경계는 원래대로 둔다. 문장 끝 한 글자를 고립시켜 짧은 자막으로 만들지 않는다. 실제 Whisper 단계 기록에서 원래 분리된 뒷발언이 이 경로로 앞 자막에 들어가는 사례를 확인했다. 원래 발언 경계는 화자 분리 정답을 뜻하지는 않는다.

진단의 `timing_uncertain_units`는 음향 대조 전 남아 있는 불확실한 단어 조각 수이며 오류율이 아니다. 최종 VTT에는 내부 표시를 넣지 않는다.

### 채택하지 않은 표시 후보

`acoustic_timing.display_units`는 시각 채택 결과와 화면 묶음을 분리한다. 보정 번호와 실제 발언 경계는 다른 개념이며, 같은 채택 결과를 다음 세 방식으로 비교할 수 있다.

- `legacy`: 기존 표시 경계 유지. **운영 기본값**이다. 위의 정보 보존·발언 경계 보호 수정은 이 경로에도 적용된다.
- `source`: 원래 발언 경계를 기준으로 보정 성공/실패 덩어리 사이의 처리 경계를 제거한다. 실제 비교에서 일부 뒷문구의 표시가 기존보다 최대 약5.14초 앞당겨져 기본값으로 채택하지 않았다.
- `supported`: 양쪽 끝을 음향으로 확인한 덩어리끼리만 처리 경계를 제거한다. 약한 원문 조각이나 시작만 보정한 덩어리와는 합치지 않는다. 이 방식도 기본값으로 채택하지 않았다. 정답 없이 묶음 감소를 품질 개선이라고 판정하지 않는다.

이 둘은 비교 도구에서만 시험하며 서비스 설정이나 사용자 화면에 선택 항목을 추가하지 않는다. 운영 추출의 표시 정책은 진단과 단계 기록에 `legacy`로 명시된다.

`acoustic_resolved`에는 이웃 침범 검사까지 끝난 채택 결과가 남는다. 비교 도구는 같은 시각으로 두 후보를 만들므로 모델을 재인식해서 문구가 달라지는 혼동이 없다. `display_exposure`는 묶음이 달라져도 같은 글자가 화면에 나타나는 시각의 차이를 기록한다. 글자별 발음 시각을 만들어내는 지표가 아니며, 표시를 합쳐 짧은 자막 수만 줄이는 부작용을 드러내기 위한 것이다.

두 작품의 고정된300초 원문에 대한 서버 비교는 기존 결과를2ms 이내로 재현한 뒤 수행했다. Qwen의24개 실제 정렬 창에서는 불확실성 표시를 보존해도 원문과 표시용 단어 시각이 동일했고, 창 연결 뒤 원문도 유지됐다. 한국어·영어는 기존 실제 추출 기록의 표시 단계 재생을 확인했으며 이번에 새로 인식하지 않았다. 추가 시험과 비공개 상세 결과는 로컬 `worklog.md`와 Git에서 제외된 `data/subtitle-evaluation/`에 남긴다. 사람 검수 정답이나 다른 언어 전체의 품질 보증은 아니다.

최종 경계 보호 수정은 같은 세 작품의 Whisper 원문과 서버 원음으로 다시 대조했다. 두 작품의각300초는 기존 자막 내용·시각과 같았다. 개발 자료600초에서는 원래 뒤 발언이 앞 자막에 들어가 약3.07초 먼저 표시되던 한 묶음을 분리했다. 앞 발언의 끝과 뒤 발언의 원래 시작·끝을 보존했고, 짧은 끝 글자가 새로 생기지 않았다. 모델은 서버의 제한된 검사 컨테이너에서만 실행했다. 운영 서비스·기존 자막은 변경하지 않았으며, 새 정책은 업데이트 후 새로 추출하는 자막에 적용된다.
